# MVP 入口与原生回退验证

本文件属于阶段 A，可行性验证完成后再继续相关 MVP 入口实现。原生回退尚未证实。独立验证工程：`srcs/entry-probe/`；可加载副本：`bin/entry-probe/`。本工具不包含已通过的美化界面，不是本轮 MVP 首版。

## 用户操作

1. 在 Edge 打开 `edge://extensions/`，开启“开发人员模式”。若已有接管新标签页的其他扩展，暂时关闭它们并记住原状态。
2. 点击“加载解压缩的扩展”，选择项目 `bin/entry-probe/` 文件夹。确认名称为“ZJUers 新标签页入口验证”。若 Edge 提示新标签页已更改，选择保留本验证扩展的更改。
3. 点击“+”，确认出现验证页面。点击“在当前标签页打开 zjuers.com”，确认原站正常加载。
4. 点击工具栏的验证扩展图标返回验证页（必要时先从拼图菜单选择该扩展）。依次测试三个原生页面候选按钮，每次记录是原生 Edge 页面、验证页还是错误页。三个地址均只是候选，不代表官方支持绕过覆盖。
5. 返回验证页，点击“复制记录”，把记录和第 4 步三个观察结果发给 AI，同时提供 `edge://version/` 中的 Edge 版本号即可，不需要用户目录等其他内容。

当前不需要配置 Edge 启动页。验证结束后可关闭本验证扩展，恢复第 1 步暂时关闭的扩展。验证扩展没有自动导航，重复进入验证页不会循环跳转。

## 权限与验证界限

诊断工具使用 storage 保存会话记录，tabs 读取手动验证标签的最终地址，webNavigation 观察主文档导航错误；网站权限限于 `https://zjuers.com/*`。不会收集其他标签页记录或上传内容。正式 MVP 将重新按需要收窄权限。

只有实际观察到原生页面且不再次进入验证扩展，才确认该候选在当前 Edge 版本下有效；浏览器接受导航请求不等于回退成功。若所有候选失败，记录证据并由用户决定替代方案。原站失败的自动触发验证在确定回退目标后执行，分别检查离线、DNS／连接错误、HTTP 主文档错误及避免循环；不把慢加载或局部资源错误当成原站不可达。

## 第一轮实际验证结果（2026-10-01）

用户在 Edge 加载入口验证扩展后确认：原站按钮可以进入完整页面；edge://newtab/ 返回验证页；edge://new-tab-page/ 和 chrome://new-tab-page/ 均为浏览器错误页。用户提供的日志显示原站导航 loading → complete，edge://newtab/ 后再次出现验证页；两个 new-tab-page 候选均出现 net::ERR_INVALID_URL，chrome:// 地址会转为 edge:// 地址。

结论仅限本轮实测：chrome_url_overrides 启用时，上述候选不能满足原生回退要求。未证明所有其他方案都不可行。

建议另行验证不声明 chrome_url_overrides、通过 tabs.onCreated/onUpdated 只识别新创建标签并转到原站的方案；该方案保留原生新标签页，原站导航失败时在同一标签恢复 edge://newtab/，通过每标签状态避免再次重定向。候选方案尚待用户确认和 Edge 实测，可能出现短暂原生页面及地址栏焦点变化。不得因此提前宣称原生回退可用。

## 第二轮验证准备

用户已批准验证事件驱动的一次性跳转路径。第二轮工具见 bin/redirect-probe/，操作说明见 docs/redirect-probe.md。需先关闭第一轮覆盖型验证扩展，否则它仍会接管原生页并干扰回退。当前已完成状态逻辑、语法与打包检查，实际 Edge 结果待用户提供。
