# 第二轮：保留原生页的跳转路径验证

工程：`srcs/redirect-probe/`；加载副本：`bin/redirect-probe/`。此工具没有 chrome_url_overrides，不包含正式首页美化。只对安装后新建的普通标签进行识别，原站加载成功后不再干预该标签。控制页从扩展工具栏图标打开。

## 加载与测试

1. 在 `edge://extensions/` 中关闭第一轮“ZJUers 新标签页入口验证”扩展，以及其他覆盖新标签页的扩展。先点击“+”，确认 Edge 原生新标签页可正常出现。
2. 点击“加载解压缩的扩展”，选择项目 `bin/redirect-probe/`。名称应是“ZJUers 新建标签跳转验证”。不要同时启用第一轮工具。
3. 从工具栏拼图菜单点击本扩展，进入控制页。选择“正常：跳转原站”，等当前模式文字更新后点击“+”；再用 Ctrl+T 测试一次。应进入原站完整页面。观察是否闪现原生页、打开后键盘焦点在哪里，以及标签数量是否只增加一个。
4. 回到控制页，选择“模拟连接失败：返回原生页”，等待模式文字更新，再点击“+”。应停留在真正的 Edge 原生新标签页；等待数秒并刷新该标签，检查是否仍停留而没有反复跳转。再打开另一个新标签，检查它也能稳定回退。
5. 在控制页复制记录，将记录和上述观察结果交给 AI。如未跳转，请说明“+”和 Ctrl+T 是否一致；也可提供 Edge 版本号。
6. 测试完成选择“关闭跳转”，或在扩展管理页关闭本工具。Edge 启动页设置暂不用修改。

## 模拟与真实失败的区别

模拟模式不访问虚假地址，也不改变网络环境；识别新标签后，直接调用与连接失败相同的回退状态处理。这验证原生页面可达与不循环机制，不证明实际离线、DNS 错误或 HTTP 错误都能捕获。

正常模式监听原站主文档导航错误，针对明确的离线、DNS、连接及代理错误回退。用户取消导航、子资源失败、其他目标网站失败不触发回退。本轮不使用超时强制跳转，不覆盖浏览器证书警告，尚未实现 HTTP 状态检测。候选路径通过后继续这些触发条件验证。

## 权限和数据

与上一轮相同，使用 tabs、storage、webNavigation，网站权限限于原站。状态和记录仅在浏览器会话内保存。只记录已识别的新标签跳转／回退，不记录普通网站标签的导航；URL 查询参数不写入记录。状态先保存再导航，服务工作线程重启后可恢复单标签状态。无自动重试、无上传、新依赖或系统修改。

## 自动检查

四项 Node 状态逻辑测试覆盖一次跳转与不循环、普通导航和取消不回退、模拟失败以及成功／关闭模式；通过 JavaScript 语法及清单／副本路径检查。真实 Edge 行为由用户执行上述步骤后确认。

若工具栏扩展列表中找不到第二轮工具，请先在 edge://extensions/ 检查是否存在“ZJUers 新建标签跳转验证”且已开启。0.0.3 版增加自定义图标和 options_page；点击该扩展卡片的刷新按钮后，可从“详细信息”中的“扩展选项”打开控制页，无需依赖工具栏图标。若管理页也无此扩展，需要重新加载 bin/redirect-probe/，并记录加载错误。

## 第 0.0.4 版：真实断网失败诊断

用户确认正常跳转速度可接受，但真实断网后仍停留原站错误页。不能凭浏览器中文提示确定底层错误码。先前工具仅在状态变化时记录错误，未匹配的错误或已经变化的状态没有原始错误记录，无法区分错误码未覆盖与事件先后次序问题。

0.0.4 增加原站主文档的原始错误（含错误码与处理前阶段），以及跳转中标签更新的 currentUrl／pendingUrl／changedUrl。当前不改变回退策略，不把诊断更新称为已修复。请在 edge://extensions/ 刷新本工具，控制页选择正常模式后断网新建标签，回到控制页复制记录；先测试一次即可。日志不依赖外网，可在恢复网络前复制。若没有原始错误，则继续根据标签事件定位，不盲目增加跳转条件。

## 第 0.0.5 版：修正新标签页过渡事件误判

用户日志明确显示：请求原站后约 40ms，标签报告 chrome-extension://pcpnigdkpcgemocnjhebmajldpjlbeom/newtab-ext.html，旧策略因此把 redirecting 改为 ignored；随后原站报 net::ERR_CONNECTION_CLOSED，错误本在支持清单中，但阶段已被停用，所以没有回退。0.0.5 在等待原站导航结果期间容许这个实测的新标签页实现地址作为过渡事件，其他网址仍停止处理。此地址来自当前用户环境，正式实现时需继续核对跨版本兼容性，不称为公开官方接口。

新增按真实日志事件顺序的回归测试：修复前失败，修复后六项测试全部通过。请在 Edge 刷新扩展，确认版本 0.0.5，正常模式下断网新建标签复测，并观察回退后刷新是否仍稳定；网络恢复后另建标签应正常进入原站。源码修复和模拟回归通过不等同真实 Edge 回退验收通过。

## 第 0.0.5 版实际复测记录

用户日志显示正常标签从 watching → redirecting → ready；断网标签于 2026-10-01T07:30:46.659Z 报 ERR_CONNECTION_CLOSED，随后保持 redirecting 并转 fallback，执行 open-native。后续完成事件地址为先前识别的新标签页实现页，约 4 秒内多次完成事件均未再次出现 open-home；恢复网络后另一新标签转 ready。说明代码层的真实错误触发、回退导航与单标签防循环已得到实测日志支持。

最早一条“回退标签完成加载”仍是原站地址，不能视作原生页成功证据；该记录名称仅代表当时标签阶段为 fallback，不代表完成事件必定对应回退目标。后续由用户确认画面确为 Edge 原生页，才能完成可行性结论；不同网络错误和 HTTP 状态仍需后续独立验证。

## 重要更正：0.0.5 原生页面仍被阻止

用户明确说明回退后的实际页面显示“pcpnigdkpcgemocnjhebmajldpjlbeom 的行为被 Microsoft Edge 阻止”。因此，先前日志中的内部地址和完成事件不代表原生页面成功；实际回退路径仍未通过。此前“回退标签完成加载”记录名过度表达结果，0.0.6 改为中性完成事件并注明必须查看画面。

0.0.6 增加独立手动“创建默认新标签（不跳转原站）”测试，通过 tabs.create 不指定 url，由浏览器选择默认页。该标签标记为不跳转，保留当前控制页及全部既有标签；不自动关闭失败标签，不替换当前回退策略。此实验只验证不同创建路径是否避开当前内部页导航阻止，成功与否以用户实际画面为准。若成功，再讨论是否用新标签替换失败标签作为产品回退方案。

## 第 0.0.6 版用户画面确认

用户明确确认：CREATE_NATIVE（tabs.create 省略 URL）能够显示可用的 Edge 原生新标签页；正常模式新标签进入完整原站；模拟失败模式仍被 Edge 阻止。日志中模拟分支使用 open-native（tabs.update 指定 edge://newtab/），因此并未使用新增的默认标签创建路径。这次两个结果须分别记录：创建默认标签已取得用户画面证据，当前标签直接导航回退仍不可用。

建议失败时以默认新标签替换失败标签：先在原窗口相邻位置创建无 URL 默认标签并标记为跳过重定向，创建成功后关闭本次原站入口的失败标签。若创建失败，保留旧标签并报告错误。该策略改变 tabId，需检查标签位置、激活状态和标签组；本轮诊断阶段先验模拟及断网，不提前认定正式 MVP 回退通过。自动关闭失败入口标签的产品行为待用户确认。

## 第 0.0.7 版：经用户确认采用创建后替换

最终用户复测结论：用户确认该替换方案可行，并授权继续完成 MVP。此结果用于结束独立入口可行性关口；正式包仍需再次安装与交互审阅。

用户批准默认新标签替换方式。回退不再对失败标签导航到 edge://newtab/，改为省略 URL 创建默认标签，先标记 native-return 跳过原站重定向，再关闭失败入口。尽量保留窗口、位置、激活、固定及标签组。创建或标记失败时不关闭旧标签；创建期间原标签发生其他导航也保留旧标签。失败阶段先持久化，重复错误不会重复替换。未新增权限或依赖。
